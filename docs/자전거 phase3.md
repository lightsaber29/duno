# Duno 두 번째 버전 기획서

| 항목 | 내용 |
|---|---|
| 작성일 | 2026-10-16 |
| 작성 | PM |
| 대상 | 개발 담당 |
| 화면 예시 | Duno 두 번째 버전 시각화 |

## 1. 개요

두 번째 버전은 지금의 날짜별 투두에 핵심목표, 카테고리, 할 일별 시간 기록을 추가한다. 사용자는 계획한 카테고리 비율과 실제로 쓴 시간의 차이를 확인한다.

문서 규칙은 다음과 같다.

- 화면 구성, 레이아웃, 디자인, 데이터 구조, 알림 구현 방식은 개발 담당이 정한다.
- 화면 문구는 반말이다. 문서에 적은 문구는 예시다.
- "(확인 중)"이 붙은 요구사항은 현재 내용대로 구현한다. PM 확인 뒤 바뀔 수 있다.
- "(예시)"가 붙은 내용은 형태를 보여 주기 위한 것이다. 형태는 개발 담당이 정한다.
- 7절의 미정 사항은 구현하지 않는다.

## 2. 용어

| 용어 | 정의 |
|---|---|
| 핵심목표 | 사용자가 이루고 싶은 일. 한 줄로 적는 끝나지 않는 이상향 |
| 카테고리 | 핵심목표를 위해 시간을 쓰는 영역. 최대 5개 |
| 기타 | 어느 카테고리에도 속하지 않는 할 일이 들어가는 곳. 카테고리 개수에 포함하지 않는다 |
| 핵심목표 비율 | 진입에서 정하는 카테고리별 시간 비율(%). 합계 100% |
| 주간 목표 | 주마다 적는 목표 한 줄 |
| 주간 비율 | 주마다 정하는 카테고리별 시간 비율(%). 합계 100% |
| 주간 목표 시간 | 한 주에 핵심목표를 위해 쓸 시간 |
| 실제 비율 | 기간 안에서 카테고리에 기록한 시간이 전체 기록 시간에서 차지하는 비율 |
| 편향 | 실제 비율과 기준 비율(핵심목표 비율 또는 주간 비율)의 차이 |

## 3. 우선순위

MoSCoW 방식으로 나눈다. Must는 반드시 필요한 기능, Should는 필요한 기능, Could는 다음 버전 후보, Won't는 제외 기능이다. 이번 버전은 Must와 Should를 구현한다.

| 등급 | 기능 | 연결되는 기존 화면 | 요구사항 |
|---|---|---|---|
| Must | 진입 | 로그인 다음, 메인 이전 | 4.1 |
| Must | 할 일 + 카테고리 | 메인의 할 일 입력, 일간 목록 | 4.2 |
| Must | 저녁 회고 | 메인 일간 목록의 할 일 | 4.3 |
| Must | 편향 보기 (핵심목표 비율 기준) | 메인 | 4.4 |
| Should | 할 일 입력 권유 | 메인의 할 일 입력 | 4.5 |
| Should | 회고 알림 | 저녁 회고 | 4.6 |
| Should | 주간 목표 + 주간 비율 | 메인의 주간 목표 | 4.7 |
| Should | 주간 마감 수정 | 기존 주간 마감 | 4.8 |

Could (다음 버전 후보)

- 편향 보기의 "최근 4주" 기간
- 편향 보기의 카테고리 상세 (기록 시간, 주별 시간, 할 일 목록)
- 저녁 회고의 목록 밖 할 일 추가
- 저녁 회고의 한 줄 회고
- 이틀 전까지 회고 작성

Won't (제외)

- 마감 표시
- 카테고리 자동 분류, AI 그룹핑, AI 추천
- 타이머, 시간대별 일정
- 주간 목표 완료율

## 4. 요구사항

### 4.1 진입

목적: 핵심목표는 이루고 싶은 일을 적고 그것을 기준으로 기록을 연결하는 앵커다. 카테고리는 나중에 AI가 카테고리와 피라미드 구조를 바탕으로 그룹핑할 때 기준이 된다.

| ID | 요구사항 |
|---|---|
| ON-1 | 핵심목표가 없는 사용자는 진입을 완료해야 메인으로 이동한다. 진입은 건너뛸 수 없다 |
| ON-2 | 핵심목표를 한 줄로 입력받는다 |
| ON-3 | 카테고리를 최대 5개 입력받는다 |
| ON-4 | 카테고리별 핵심목표 비율을 입력받는다. 기본값은 균등 분배다. 합계가 100%가 아니면 다음으로 진행할 수 없다 |
| ON-5 | 주간 목표 시간을 입력받는다. 입력한 값은 매주 같은 값으로 적용한다 |

핵심목표 비율의 목적: 처음 정한 목표 비율과 비교하는 기준이다.
주간 목표 시간의 목적: 편향이 있더라도 그 주에 일을 했는지 판단하는 기준이다.

### 4.2 할 일 + 카테고리

목적: 하루 동안 앱을 쓰는 흐름을 만들고 한 일을 카테고리에 연결한다 (확인 중).

| ID | 요구사항 |
|---|---|
| TD-1 | 할 일을 추가할 때 사용자가 카테고리를 선택한다 |
| TD-2 | 카테고리 표시 방식: 할 일 옆 라벨, 라벨을 눌러 변경 (예시) |
| TD-3 | 카테고리 이름을 바꾸거나 삭제해도 해당 카테고리에 기록된 시간 총량을 유지한다 |
| TD-4 | 메인의 주간 목표 완료율 배지를 제거한다 |
| TD-5 | 날짜별 달성 링은 유지한다 |
| TD-6 | 전날 완료하지 않은 할 일은 다음 날로 옮기지 않는다 (확인 중) |
| TD-7 | 주의 시작은 월요일이다 |

### 4.3 저녁 회고

목적: 할 일마다 시간을 기록해 실제 비율을 계산할 수 있게 한다 (확인 중).

| ID | 요구사항 |
|---|---|
| RV-1 | 그날의 할 일을 모두 표시하고 할 일마다 시간과 분을 숫자로 입력받는다 |
| RV-2 | 완료 체크 여부와 관계없이 입력한 시간을 계산에 포함한다 |

### 4.4 편향 보기

목적: 사용자가 편향을 알아차리고 편향의 반대쪽 일을 작은 단위로 하게 한다.

| ID | 요구사항 |
|---|---|
| BI-1 | 메인에서 편향 보기로 이동할 수 있다. 위치는 개발 담당이 정한다 |
| BI-2 | 핵심목표 비율과 지금까지의 실제 비율을 카테고리별로 비교해 표시한다 |
| BI-3 | 편향이 15를 넘는 카테고리를 구분해 표시한다 |
| BI-4 | 기타는 편향 판정에서 제외하고 실제 비율 계산에는 포함한다 |
| BI-5 | 편향 표시 문구: 더 / 덜 / 계획대로 (예시) |

### 4.5 할 일 입력 권유

목적: 사용자는 주간 목표 때문에 덜 쓴 카테고리의 일을 하지 않는다. 권유는 그 카테고리를 리마인드하고 할 일 하나를 실제로 실행하게 한다.

| ID | 요구사항 |
|---|---|
| NU-1 | 할 일 입력 영역에 표시한다 |
| NU-2 | 핵심목표 비율 대비 지금까지의 실제 비율이 15 넘게 낮은 카테고리가 있을 때만 표시한다 |
| NU-3 | 카테고리 1개와 할 일 1개를 제시한다 |
| NU-4 | 해당 카테고리의 지난 할 일 중 기록 시간이 가장 짧은 할 일을 제시한다 |
| NU-5 | 해당 카테고리에 지난 할 일이 없으면 카테고리만 제시한다 |
| NU-6 | 사용자가 닫으면 그날은 다시 표시하지 않는다 |
| NU-7 | 제시한 할 일을 누르면 오늘 할 일 목록에 추가한다 (확인 중) |
| NU-8 | 제시한 할 일이 그 주 안에 완료 체크되고 저녁 회고에 시간이 입력되면 성공으로 본다 |

문구 예시: `포트폴리오에 계획보다 시간을 덜 썼어 · [+ 케이스 스터디 목차 30분] [닫기]`

### 4.6 회고 알림

목적: 알림에서 회고 작성까지 이어지게 한다.

| ID | 요구사항 |
|---|---|
| NT-1 | 알림을 누르면 저녁 회고 화면을 연다 |
| NT-2 | 알림 시각은 저녁 9시다 (확인 중) |
| NT-3 | 메인에 저녁 회고로 이동하는 버튼을 둔다 (확인 중) |

### 4.7 주간 목표 + 주간 비율

목적: 주마다 어떤 일을 목표로 카테고리 비율을 정했는지 구별해서 보고 그 주를 비교하는 기준으로 쓴다.

| ID | 요구사항 |
|---|---|
| WG-1 | 주마다 주간 목표와 주간 비율을 함께 저장한다. 주간 비율의 합계는 100%다 |
| WG-2 | 편향 보기에서 "이번 주"를 선택하면 그 주의 주간 비율과 실제 비율을 비교한다 |
| WG-3 | 편향 보기에서 다른 주를 선택해 볼 수 있다 |
| WG-4 | 주간 비율은 주간 마감에서 정한다 (확인 중) |
| WG-5 | 진입 직후 첫 주의 주간 비율은 핵심목표 비율과 같다 (확인 중) |

### 4.8 주간 마감 수정

목적: 사용자가 회고하고 계획이나 카테고리를 바꿀지 리마인드한다. 주간 마감이 없으면 사용자는 잊어버려서 바꾸지 않는다. 주간 마감을 거친 사용자는 다음 주에 주간 목표가 달라진다. 지난주를 보고 무언가를 바꾸면 성공으로 본다.

| ID | 요구사항 |
|---|---|
| WC-1 | 주가 바뀐 뒤 앱을 처음 열 때 표시하는 기존 동작을 유지한다 |
| WC-2 | 기존 완료율 숫자를 제거한다 |
| WC-3 | 지난주 기록 시간(기타 포함)과 주간 목표 시간을 함께 표시한다 |
| WC-4 | 지난주 기록 시간이 주간 목표 시간 이상이면 "했다"로 표시한다 |
| WC-5 | 지난주 편향을 그 주의 주간 비율 기준으로 표시한다 (확인 중) |
| WC-6 | 다음 주의 주간 목표를 입력하거나 수정한다 |
| WC-7 | 주간 목표 시간을 수정할 수 있다. 수정한 값은 다음 주부터 적용한다 |
| WC-8 | 다음 주의 주간 비율을 수정할 수 있다 (확인 중) |
| WC-9 | 카테고리를 추가, 이름 변경, 삭제할 수 있다 (확인 중) |
| WC-10 | 핵심목표 비율은 주간 마감에서 수정하지 않는다 (확인 중) |
| WC-11 | 사용자가 무언가를 바꿨는지 기록한다. 기록 방식은 개발 담당이 정한다 (확인 중) |

## 5. 계산 규칙

| 값 | 계산 |
|---|---|
| 카테고리 시간 | 기간 안에서 해당 카테고리 할 일에 입력한 시간의 합 |
| 실제 비율 | 카테고리 시간 ÷ 기간 안의 전체 입력 시간 × 100 |
| 편향 | 실제 비율 − 기준 비율 |
| 주간 달성 | 그 주 전체 입력 시간(기타 포함) ≥ 주간 목표 시간이면 "했다" |

## 6. 기준 비율과 기간

| 비교 | 기준 비율 | 기간 | 등급 |
|---|---|---|---|
| 처음 목표 비교 | 핵심목표 비율 | 지금까지 | Must |
| 그 주 비교 | 주간 비율 | 선택한 주 | Should |
| 처음 목표 비교 | 핵심목표 비율 | 최근 4주 | Could |

## 7. 미정 사항

| 항목 | 관련 |
|---|---|
| 주간 목표 시간에 못 미친 주의 표시 | WC-4 |
| 핵심목표 비율로 "시간을 어느 정도 써야 하는지"를 보여 주는 방법 | 4.1 |
| 편향 기준 15의 단위 (% 또는 %p) | BI-3, NU-2 |
| 편향 보기 화면 이름, 처음 열 때 선택된 기간 | 4.4 |
| 카테고리 선택 방식, 비율 입력 방식 | ON-3, ON-4 |
| 권유 대상 카테고리가 여럿일 때, 가장 짧은 할 일이 0분이거나 같은 시간이 여럿일 때 | NU-3, NU-4 |
| 주간 마감의 요일별 달성 링, 잘된 점과 아쉬운 점, 지난주 못 끝낸 일 가져오기 유지 여부 | 4.8 |
| 정보 수집 동의 화면, 쉬는 날 기록, 연속 기록 일수 | |
| 화면에 "편향"이라는 용어를 쓸지 | |
