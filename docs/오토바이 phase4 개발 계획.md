# 오토바이 phase4 개발 계획

기준일: 2026-10-16 · 기준 문서: `오토바이 phase4.md`(PM 기획서, 문서 안에서는 "Duno 두 번째 버전") · 화면 예시 링크(claude.ai 아티팩트)는 이 계정으로 열리지 않아 보지 못함

## 한 줄 요약

phase3 기획서의 **개정판**이에요. 새 기능은 거의 없고, 8절 "미정 사항"이 "임시 처리대로 구현"으로 바뀌면서 지금 구현과 다른 규칙 13가지를 맞추는 일이 대부분이에요. 큰 것은 **회고를 당일만**, **하루 24시간 넘으면 저장 막기**, **"지금까지"를 진입일부터**, **주간 비율이 없는 주는 핵심목표 비율**, **지운 카테고리 시간은 총량에만**, **비율 스냅샷 저장**이에요.

## 먼저 알아 둘 점

- 1.1절 "지금 있는 기능"은 phase1 상태(완료율 배지, 지난주 읽기 전용 등)로 적혀 있어요. phase2·3에서 바뀐 지금 앱과 달라요. 이 절은 무시하고 지금 앱 기준으로 대조했어요.
- 8절 규칙이 바뀌었어요. phase3은 "미정 사항은 구현하지 않는다", phase4는 "**적힌 임시 처리대로 구현한다**"예요. 그래서 phase3에서 제가 정한 기본값 중 몇 개가 PM의 임시 처리와 달라 바꿔야 해요.
- 그 밖의 요구사항(진입, 라벨, 배지 제거, 달성 링, 주간 마감 구성, 반말 등)은 phase3 그대로라 이미 되어 있어요.

## 검토 결과: 바로 개발 가능한가

**거의 다 가능해요.** 문서가 미정 사항마다 임시 처리를 적어 줘서 빈칸이 적어요. 남은 4개는 2026-10-16에 모두 정했어요.

### 정한 것 (E1~E4)

| # | 빈칸 | 추천안 |
| --- | --- | --- |
| E1 | 회고 알림(실제 푸시)이 Should로 다시 들어옴 | **하지 않음** (phase3 결정 유지). 9시 이후 앱 안 띠만 |
| E2 | **회고를 당일만으로 줄이기(RV-3)** | 기획서 Must라 **따름**: 날짜 탭을 없애요. phase3에서 Could(지난 날짜 회고)로 남겨 뒀던 기능을 지우는 거라 확인해요. 목록 밖 할 일 추가와 한 줄 회고(여전히 Could)는 phase3처럼 **그대로 둬요** |
| E3 | **새 할 일의 카테고리 기본값 기타(TD-1)를 매번 되돌릴지** | 화면을 열 때마다 기본은 기타, 하나 고르면 그 화면에서는 유지(연달아 같은 카테고리 적기 편하게). 매번 기타로 되돌리기를 원하면 알려 주세요 |
| E4 | **이미 진입한 계정의 "진입일"** (BI-3) | 진입일 칸 `profiles.started_on`을 새로 두고 앞으로 진입하는 계정은 진입을 마친 날(기기 날짜)을 저장. 이미 진입한 계정은 **첫 카테고리를 만든 날**(진입 저장 때 카테고리를 먼저 만들어서 앱으로 진입한 계정은 사실상 정확). seed는 진입일을 직접 넣음. 다른 안(적용일부터·한 번 묻기·다시 진입·첫 기록일)은 비교 뒤 뺌 |

### 제가 정하고 갈 것 (다르면 알려 주세요)

- **회고 저장 방식 (RV-6 때문에)**: 지금은 칸을 벗어날 때마다 저장하는데, 그러면 24시간 넘는 중간 상태가 저장될 수 있어요. **"저장"을 눌러야만 저장**하고, 합계가 24시간을 넘으면 경고를 띄우고 저장 버튼을 꺼요. "돌아가기"는 저장하지 않아요. 목록 밖 할 일 추가도 합계에 넣어서 넘으면 막아요.
- **"기록한 날"**: 회고에서 저장을 누르면 그날에 저장 표시를 남겨요(시간이 다 0분이어도).
- **0 기록 권유 문구**: 실제 비율이 없을 때도 "제작에 계획보다 시간을 덜 썼어" 그대로 써요(실제 0% < 계획).
- **스냅샷 내용**: 그 시각, 카테고리별 이름과 핵심목표 비율 목록.
- **지운 카테고리 할 일의 라벨**: 지금처럼 원래 이름에 회색(TD-4는 편향 보기 목록에 대한 규칙).
- **편향 보기의 주 탭**: 진입한 주부터 이번 주까지 모두(가로로 넘겨 봄). "최근 4주" 탭(Could)은 phase3처럼 그대로 둬요.
- **문장의 "치우침"**: 진입 안내 "비율이 치우쳤더라도…"와 판정 "치우침 없이 계획대로…"를 "더/덜/계획대로"만 쓰게 바꿔요.

## 진행 순서

단계마다 커밋해요. 2026-10-16 사용자 요청으로 단계마다 멈추지 않고 끝까지 진행하고, PR만 승인받아요. 1~7단계 모두 끝남 (브랜치 `todo-phase4`).

1. **스키마**: `supabase/phase4.sql`(진입일·스냅샷·회고 저장 표시). 로컬 Postgres에서 phase3 데이터 위에 실행해 보고, 사용자가 Supabase에서 실행
2. **계산**: 경계 15 이상, 주간 비율 이어 쓰기 없앰, 지운 카테고리 분모만, 기록 0 처리, 권유 0 기록, 회고 합계 검사. 테스트
3. **저녁 회고**: 당일만, "저장"으로만 저장, 24시간 막기, 저장 표시, 9시 안내 띠 조건
4. **편향 보기**: 이름, 진입일부터의 "지금까지", 진입한 주부터의 주 탭, 기록 0 표시, 지운 카테고리 숨김, "치우침" 문구 정리
5. **메인·권유·진입**: 새 할 일 기본 기타, 기록 0 권유, 진입 예시 문구, 진입일 저장
6. **주간 마감**: 주간 비율 기본값 = 핵심목표 비율, 카테고리 더하기·지우기 때 스냅샷
7. **마무리**: seed를 phase4 데이터로(진입일 직접 넣기), README, 진짜 Supabase로 확인

## 구현하며 정한 것

- 회고: "저장"으로만 저장. 저장 안 한 게 있으면 돌아가기 버튼이 "저장 안 하고 나가기"로 바뀌어요(확인 창 대신). 합계가 24시간을 넘으면 경고와 함께 저장·목록 밖 할 일 추가를 막아요. 카테고리 라벨 바꾸기는 지금처럼 바로 저장.
- 회고 안내 문구: "회고는 오늘만 쓸 수 있어." 화면 제목 "오늘 회고".
- 편향 보기: 기록이 0이면 정한 막대만 보이고 실제 막대·더/덜은 숨겨요. 판정 문장은 "모두 계획대로 쓰고 있어." / "리서치에 계획보다 더 썼고 제작에 덜 썼어."
- 편향 보기 데이터는 최근 4주와 진입한 주 중 이른 쪽부터 불러와요. "최근 4주" 탭(Could)은 진입일과 상관없이 최근 4주.
- 지운 카테고리 몫이 빠져서 편향 보기 카드의 실제 비율 합이 100보다 작을 수 있어요(빠진 만큼이 지운 카테고리).
- 권유: 진입일부터의 기록으로 계산. 기록 0일 때 문구도 "…에 계획보다 시간을 덜 썼어".
- 진입 3단계 안내: "카테고리 비율과 상관없이 그 주에 일을 했는지 보는 기준이야."
- 진입일은 진입을 마친 날의 기기 날짜를 앱이 넣어요(할 일 날짜와 같은 기준).
- 스냅샷은 카테고리를 더하거나 지울 때만(이름만 바꾸면 남기지 않음).
- 마감 저장이 여러 번 나눠 일어나는 점은 phase3과 같아요(스냅샷이 하나 더 늘어남).
