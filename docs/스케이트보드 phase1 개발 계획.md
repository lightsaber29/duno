# 스케이트보드 phase1 개발 계획

기준일: 2026-10-15 · 기준 문서: `스케이트보드 phase1.md`(원페이저), `스케이트보드 phase1.html`(프로토타입)

## 한 줄 요약

기존 Duno 코드에서 로그인과 Supabase 연결만 남기고, 원페이저의 화면 하나와 주간 마감 흐름을 새로 만들어요. 단계마다 멈추고 확인받은 뒤 다음 단계로 넘어가요.

## 원페이저와 달라지는 점 (2026-10-15 결정)

원페이저는 고치지 않고, 달라지는 점을 여기에 적어 둬요.

| 항목 | 원페이저·프로토타입 | phase1 결정 |
| --- | --- | --- |
| 저장 | 언급 없음 | 기존 Supabase + Google 로그인 재사용. 기기를 바꿔도 이어짐 |
| 어제 못한 일 | 원페이저: 그대로 둠 / 프로토타입: 가져오기 배너 | **그대로 둠.** 배너는 만들지 않음. 다음 주로 넘기는 건 마감 흐름의 복사만 |
| 지난 기록 | "일요일이 지나면 고정" (방법 없음) | **이번 주보다 앞선 날짜는 읽기 전용.** 체크·추가·수정·삭제·목표 수정 모두 막음. 그래서 완료율을 따로 저장하지 않고 계산해도 바뀌지 않음 |
| 할 일 수정·삭제 | 범위 밖 (추가·체크만) | **수정·삭제 둘 다 넣음** |
| 마감 흐름이 뜨는 조건 | "주가 끝난 뒤 처음 열 때" | 아래 "주간 마감 흐름" 참고 |

## 데이터

`supabase/schema.sql`을 아래 두 테이블로 바꿔요. 날짜는 모두 사용자 기기의 지역 날짜(`YYYY-MM-DD`)예요.

**todos** — 할 일 한 개가 한 행

| 열 | 형태 | 메모 |
| --- | --- | --- |
| id | uuid | |
| user_id | uuid | 본인만 읽고 씀 (RLS) |
| date | date | 그날 기록 |
| text | text | 1~100자 |
| done | boolean | 기본 false |
| created_at | timestamptz | 목록 순서. 순서 바꾸기는 다음 phase 후보 |

**weeks** — 주마다 한 행, 처음 쓸 때 생성

| 열 | 형태 | 메모 |
| --- | --- | --- |
| user_id, week_start | uuid, date | 둘을 묶어 기본 키. week_start는 월요일 |
| goal | text | 0~40자. 30자 이내 권장은 화면 안내로만 |
| good, bad | text | 회고 한 줄씩, 선택, 0~40자 |
| closed_at | timestamptz | 마감 흐름을 끝냈거나 건너뛴 시각. 있으면 다시 띄우지 않음 |

- 완료율은 저장하지 않아요. 그 주 todos에서 `done 개수 / 전체 개수`로 계산해요.
- 읽기 전용은 화면에서만 막아요. 자기 데이터라 다른 사람이 피해 볼 일이 없어서 DB 제약까지는 두지 않아요.

## 화면

원페이저의 다섯 칸을 그대로 따라가요. 위에서부터 상단바, 주간 목표, 주간 줄, 일간 목록, 할 일 입력이에요.

- **상단바**: ‹ 10/13 – 10/19 ›. 이번 주가 아니면 "이번 주로" 버튼. 오른쪽 끝에 작은 "로그아웃"
- **주간 목표**: 누르면 그 자리에서 수정, Enter·바깥 누르기로 저장, Esc로 취소. 지난주는 눌러도 반응 없음
  - 배지: 지난주 "완료율 n% 기록" / 이번 주 "진행 중 n%" / 다음 주 "시작 전"
  - 비어 있을 때: 이번 주·다음 주 "목표를 적어 보세요", 지난주 "적어 둔 목표가 없어요"
- **주간 줄**: 월~일 7칸 달성 링. 오늘 표시. 누르면 일간 목록이 그날로 바뀜
- **일간 목록**: 체크하면 취소선. 할 일 글자를 누르면 수정 칸과 "삭제" 버튼이 나타남. 지난주 이전 날짜는 체크박스·수정 모두 꺼짐
- **할 일 입력**: 고른 날짜에 추가. 지난 날짜를 골랐으면 입력 칸을 숨김

## 주간 마감 흐름

**뜨는 조건** (앱을 열 때마다 확인)

1. 바로 지난주만 봐요. 몇 주 만에 열어도 그 전 주들은 건너뛰어요.
2. 지난주에 할 일도 목표도 없었으면 띄우지 않아요.
3. 지난주 `weeks.closed_at`이 비어 있을 때만 띄워요.

**두 단계**

1. 돌아보기: 지난주 목표, 완료율(할 일 n개 중 n개), 요일별 달성 링, 잘된 점·아쉬운 점 입력. "건너뛰기"를 누르면 `closed_at`만 찍고 끝나요.
2. 이번 주 목표 정하기: 아쉬운 점을 위에 보여 줘요. 이번 주 목표를 입력하고, 못 끝낸 일 목록에서 고른 일만 이번 주 월요일에 **새 할 일로 복사**해요(처음엔 모두 체크된 상태). "이번 주 시작"을 누르면 목표·회고·복사·`closed_at`을 한 번에 저장하고 일반 화면으로 돌아가요.

| 남김 | 고쳐서 씀 | 지움 |

## 진행 순서

단계가 끝날 때마다 멈추고 확인받아요. 2026-10-15 1~6단계 모두 끝남 (브랜치 `pivot/todo-phase1`).

1. **스키마**: `schema.sql` 교체. 사용자가 Supabase SQL Editor에서 실행
2. **주 계산**: `lib/week.ts`(주 시작일, 주 범위, 완료율, 마감 흐름을 띄울지)와 `week.test.ts`. `npm test`로 확인
3. **기존 코드 정리 + 기본 화면**: 상단바, 주간 줄, 일간 목록, 입력, 할 일 수정·삭제
4. **주간 목표와 읽기 전용**: 목표 수정, 배지, 지난 날짜 잠금
5. **주간 마감 흐름**: 두 단계, 복사, 건너뛰기
6. **마무리**: 로그인 문구, README, 가짜 Supabase로 화면 전체를 눌러 보기

## 구현하며 정한 것

문서에 없어서 구현 중에 정한 것들이에요.

- 빈 일간 목록 문구: 오늘 "오늘 할 일을 적어 보세요", 다른 날 "할 일을 적어 보세요", 잠긴 날 "할 일이 없어요"
- 프로토타입처럼 이번 주보다 앞선 주는 모두 "지난주 목표"로 표시해요 (3주 전도 같음)
- 마감 흐름 예시 문구의 오타 "못 놃다"는 "못 놨다"로 고쳤어요
- 마감 흐름은 앱을 열 때만 확인해요. 열어 둔 채 주가 바뀌면 새로고침해야 떠요
- 복사·목표·마감 표시는 따로 저장해요. 중간에 끊기면 다음에 열 때 복사가 한 번 더 될 수 있어요 (드문 경우라 그대로 둠, 필요하면 DB 함수로 묶기)
